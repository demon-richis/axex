# prod-hardening merge notes

`bot-verification` is based on `main`; `prod-hardening` remains a separate remote branch and was not modified. The branches diverge substantially. `prod-hardening` removes or rewrites the durable case system (`src/db/caseStore.js`, `src/utils/caseCode.js`, `src/utils/caseMenu.js`, `src/utils/caseSweeper.js`, `src/interactions/logSelectHandler.js`, and related tests), changes verification/audit paths and message/embed implementations, removes `/ping`, and changes quarantine/release behavior. It also contains Catalyst/AppSail deployment changes and a different runtime/configuration shape.

The new bot-verification event, approval interactions, bot-verification store, and tests depend on the `main` case/log conventions and should not be copied blindly onto `prod-hardening`, where those dependencies were removed. The migration itself is additive and can be reviewed independently.

Suggested merge order: first reconcile deployment/runtime and dependency changes; then restore or deliberately replace durable case logging and expiring menu behavior; then merge the bot-verification migration/store and pure classifier; then merge the configured log-channel integration, event/interaction wiring, monitors, commands, and tests. Resolve conflicts in `index.js`, `src/deploy-commands.js`, `src/interactions/buttonHandler.js`, `src/interactions/commandHandler.js`, `src/config/messages/*`, `src/db/client.js`, `src/verification/verifySystem.js`, and `src/utils/liveUpdate.js` manually. Re-run the complete test suite on a TEST deployment after each stage.
